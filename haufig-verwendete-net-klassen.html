    5. Häufig verwendete .NET-Klassen

    Hier stellen wir einige häufig verwendete Klassen der .NET-Plattform vor: Zeichenketten, Arrays, Sammlungen, Dateien und reguläre Ausdrücke. Außerdem behandeln wir LINQ (Language Integrated Query), das der Kurs von 2008 ausgelassen hat, obwohl es seit C# 3 verfügbar war: Es ist heute die gebräuchlichste Art, Sammlungen in C# zu bearbeiten. Zuvor zeigen wir Ihnen, wie Sie Informationen zu den Tausenden verfügbaren Klassen finden. Diese Anleitung ist für jeden C#-Entwickler unverzichtbar, auch für erfahrene.

    Die Beispiele dieses Kapitels – mit Ausnahme der Beispielanwendung am Ende – sind Single-File-Anwendungen , die mit [dotnet run file.cs] ausgeführt werden. Sie befinden sich im Ordner [05-classes-dotnet] des Kurscodes und laufen in der französischen Locale (fr-FR), mit Ausnahme der LINQ- und der Beispiele mit regulären Ausdrücken, die in der amerikanisch-englischen Locale (en-US) laufen.

    5.1. Hilfe zu .NET-Klassen finden

    Der Kurs von 2008 enthielt eine ausführliche Beschreibung der mit Visual Studio 2008 installierten MSDN-Hilfe samt Screenshots. Diese lokale Hilfe gibt es nicht mehr: Die .NET-Dokumentation ist heute online, kostenlos und wird mit jeder neuen Version aktualisiert.

    5.1.1. Online-Dokumentation

    Ausgangspunkt ist die Website learn.microsoft.com von Microsoft. Dort finden Sie:

    • die Dokumentation der Sprache C#: https://learn.microsoft.com/en-us/dotnet/csharp/. Sie enthält einen Überblick über die Sprache, Tutorials, die Sprachreferenz (Schlüsselwörter, Operatoren, Anweisungen) und einen Abschnitt „Neuigkeiten“, der jede Version von C# beschreibt;
    • die .NET-API-Referenz: https://learn.microsoft.com/en-us/dotnet/api/. Sie beschreibt, Namespace für Namespace, alle Klassen von .NET: ihre Konstruktoren, Eigenschaften und Methoden, mit Beispielen;
    • den API-Browser auf derselben Seite: ein Suchfeld, in das Sie den Namen einer Klasse oder Methode eingeben können ([StringBuilder], [Regex.Match] …). Über eine Dropdown-Liste wählen Sie die .NET-Version aus (hier .NET 10).

    Die Seite zu einer Klasse, etwa System.String, zeigt:

    • den Namespace der Klasse und die Assembly, die sie enthält;
    • ihre Deklaration, ihre Elternklasse und die Schnittstellen, die sie implementiert;
    • eine Liste ihrer Konstruktoren, Eigenschaften und Methoden, jeweils mit einem Link zu einer Detailseite, die die verschiedenen Überladungen, Parameter, Rückgabewerte, möglichen Ausnahmen und oft ein Beispiel zeigt;
    • Hinweise zur Verwendung.

    Die Seiten sind auf Französisch (maschinelle Übersetzung) und auf Englisch (Originaltext, der manchmal präziser ist) verfügbar. Sie können zwischen beiden wechseln, indem Sie in der URL [en-us] durch [fr-fr] ersetzen. Eine Suche mit einer Suchmaschine über den vollständigen Namen der Klasse („System.Text.StringBuilder“) führt meist direkt zur richtigen Seite.

    5.1.2. Hilfe im Editor

    Der Code-Editor (Visual Studio, Visual Studio Code mit der Erweiterung C# Dev Kit, Rider) bietet sofortige Hilfe, ohne dass Sie den Code verlassen müssen:

    • Autovervollständigung (IntelliSense): Nach der Eingabe von [aString.] schlägt der Editor eine Liste der Eigenschaften und Methoden des Objekts samt einer Kurzbeschreibung vor;
    • Tooltips: Wenn Sie den Mauszeiger über den Namen einer Klasse, Methode oder Variablen bewegen, werden ihre Deklaration und eine Zusammenfassung ihrer Dokumentation angezeigt;
    • Parameterhilfe: Wenn Sie die öffnende Klammer eines Aufrufs eingeben, zeigt der Editor die verschiedenen Überladungen der Methode und die Rolle jedes Parameters an;
    • Gehe zu Definition (Taste F12): Zeigt die Deklaration der Klasse oder Methode an. Bei einer .NET-Klasse zeigt der Editor die aus der Assembly rekonstruierten öffentlichen Deklarationen samt ihren Dokumentationskommentaren an;
    • In Visual Studio öffnet ein Druck auf die Taste F1 auf dem Namen einer Klasse oder Methode die entsprechende Seite der Online-Dokumentation.

    Diese Dokumentationskommentare, die sichtbar sind, wenn Sie den Mauszeiger über ein Element bewegen, werden auch zur Erzeugung der Online-Referenz verwendet. Ähnliche Kommentare können Sie in Ihrem eigenen Code mit der Syntax [/// <summary> ... </summary>] schreiben, die über einer Klasse oder Methode steht: Der Editor zeigt sie auf dieselbe Weise an.

    // Split und Join
string line = "one:two::three:";
// Zerlegen mit dem Trennzeichen ':'
string[] fields = line.Split(':');
for (int i = 0; i < fields.Length; i++)
{
    Console.WriteLine($"fields[{i}]=[{fields[i]}]");
}
// die Umkehroperation
Console.WriteLine($"join=[{string.Join(":", fields)}]");

// die Optionen von Split: Entfernen leerer Felder
fields = line.Split(':', StringSplitOptions.RemoveEmptyEntries);
Console.WriteLine($"RemoveEmptyEntries : {fields.Length} fields [{string.Join("|", fields)}]");

// mehrere Trennzeichen und Entfernen der Leerzeichen um die Felder
string person = " dupont , jean ;  45 ";
fields = person.Split([',', ';'], StringSplitOptions.TrimEntries);
Console.WriteLine($"TrimEntries : {fields.Length} fields [{string.Join("|", fields)}]");

// beide Optionen kombiniert
string list = "  red ,, green ,  , blue ";
fields = list.Split(',', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries);
Console.WriteLine($"both options: {fields.Length} fields [{string.Join("|", fields)}]");

// ein Trennzeichen, das eine Zeichenkette ist
string text = "apple -> pear -> apricot";
fields = text.Split(" -> ");
Console.WriteLine($"string separator: [{string.Join("|", fields)}]");

// Join akzeptiert jede Collection, nicht nur Zeichenketten
int[] numbers = [1, 2, 3, 4];
Console.WriteLine($"Join on integers: {string.Join(" + ", numbers)}");

static double[] Input()
{
    // am Anfang ist das Array leer
    double[] elements = [];
    // Eingabeschleife für die Array-Elemente
    while (true)
    {
        Console.Write($"Element (real) {elements.Length} of the array (nothing to finish): ");
        string answer = (Console.ReadLine() ?? "").Trim();
        // Ende der Eingabe bei leerer Zeichenkette
        if (answer == "")
        {
            break;
        }
        // Prüfung der Eingabe
        if (!double.TryParse(answer, out double element))
        {
            Console.WriteLine("Incorrect input, try again");
            continue;
        }
        // ein Element mehr: wir vergrößern das Array um eine Zelle
        Array.Resize(ref elements, elements.Length + 1);
        // und speichern darin das neue Element
        elements[^1] = element;
    }
    return elements;
}

// Suche der über die Tastatur eingegebenen Elemente im Array
static void Search(double[] elements, SearchType type)
{
    while (true)
    {
        Console.Write("Element searched for (nothing to stop): ");
        string answer = (Console.ReadLine() ?? "").Trim();
        // fertig?
        if (answer == "")
        {
            break;
        }
        // Prüfung
        if (!double.TryParse(answer, out double element))
        {
            Console.WriteLine("Error, try again...");
            continue;
        }
        // wir suchen das Element im Array
        int i = type == SearchType.Binary
            ? Array.BinarySearch(elements, element)    // sortiertes Array
            : Array.IndexOf(elements, element);        // beliebiges Array
        // Anzeige der Antwort
        Console.WriteLine(i >= 0 ? $"Found at position {i}" : $"Not in the array ({i})");
    }
}

    5.4. Generische Collections

    Neben Arrays gibt es verschiedene Klassen zum Speichern von Elementsammlungen. Generische Collections, die mit .NET 2.0 eingeführt wurden, befinden sich im Namespace [System.Collections.Generic], der zu den impliziten [using]-Namespaces gehört. Wir stellen zunächst zwei häufig verwendete Collections vor – die Liste und das Dictionary – und gehen dann kurz auf weitere ein.

    Der Namespace [System.Collections] enthält die älteren, nicht generischen Versionen dieser Collections, die auf .NET 1.0 zurückgehen: [ArrayList] (eine Liste), [Hashtable] (ein Dictionary) … Der Kurs von 2008 enthielt noch [ArrayList]. Diese Klassen sind heute veraltet: Sie speichern Referenzen vom Typ [object], was erfordert, die gelesenen Elemente umzuwandeln und die Zahlen in Objekte zu verpacken (Boxing), mit entsprechendem Speicher- und Zeitaufwand. Generische Collections haben diese Nachteile nicht: Eine *[List<int>] speichert ihre ganzen Zahlen direkt in einem internen *[int[]] -Array, und der Compiler prüft den Typ der hinzugefügten Elemente. [ArrayList] und [Hashtable] sollten in neuem Code nicht mehr verwendet werden.

    5.4.1. Die generische Klasse List<T>

    5.4.3. Die Klasse Dictionary<TKey,TValue>

    Die Klasse [System.Collections.Generic.Dictionary<TKey,TValue>] dient zur Implementierung eines Dictionarys. Ein Dictionary lässt sich als zweispaltiges Array auffassen:

    Schlüssel
    Wert
    key1
    value1
    key2
    value2
    ...
    ...

    In der Klasse [Dictionary<TKey,TValue>] sind die Schlüssel vom Typ [TKey], und die Werte sind vom Typ [TValue]. Schlüssel sind eindeutig: Es kann nicht zwei gleiche Schlüssel geben. Ein solches Dictionary könnte so aussehen, wenn die Typen [TKey] und [TValue] Klassen bezeichneten:

    Der dem Schlüssel [c] in einem Dictionary [d] zugeordnete Wert wird mit der Schreibweise [d[c]] ermittelt. Dieser Wert ist les- und schreibbar. So können wir schreiben:

    1

    5.5. LINQ

    Der Kurs von 2008 endete unmittelbar vor LINQ und führte dessen anonyme Typen ein, ohne sie tatsächlich zu verwenden. LINQ (Language Integrated Query, C# 3, 2007) ist eine Menge von Methoden, mit denen man eine Collection so abfragen kann, wie man eine Datenbank abfragt: filtern, sortieren, gruppieren, Summen berechnen und so weiter. Es lässt sich auf jede Collection anwenden, die die Schnittstelle [IEnumerable<T>] implementiert: Arrays, Listen, Dictionarys, Mengen, Zeilen einer Datei, Ergebnisse eines regulären Ausdrucks und, mit Entity Framework Core (Kapitel 11), Datenbanktabellen. Der Namespace [System.Linq] gehört zu den impliziten [using]-Namespaces.

    5.7.2. Die JSON-Serialisierung

    Eine Binärdatei Byte für Byte zu schreiben und zu lesen ist mühsam, und schon die kleinste Abweichung zwischen Schreiben und Lesen führt zu falschen Ergebnissen. In der Regel ist es vorzuziehen, Objekte zu serialisieren: Sie werden automatisch in eine Folge von Bytes oder Zeichen umgewandelt und anschließend deserialisiert, um sie wiederherzustellen.

    .NET stellte hierfür die Klasse [BinaryFormatter] bereit, die Objekte in ein .NET-spezifisches Binärformat serialisierte. Sie wurde inzwischen entfernt: In .NET 5 wurde sie als veraltet erklärt, und ihre Implementierung wurde in .NET 9 entfernt, da das Deserialisieren von Daten aus einer nicht vertrauenswürdigen Quelle mit [BinaryFormatter] die Ausführung beliebigen Codes erlaubte. Microsoft empfiehlt, sie durch die JSON-Serialisierung der Bibliothek [System.Text.Json] zu ersetzen, die seit .NET Core 3.0 in .NET integriert ist.

    JSON (JavaScript Object Notation) ist ein textbasiertes, menschenlesbares und universelles Format: Es ist das Austauschformat für Webdienste (Kapitel 13) und zahlreiche Konfigurationsdateien. Ein Objekt wird in geschweiften Klammern in Form von Paaren "property":value geschrieben, Arrays stehen in eckigen Klammern.

    Die statische Klasse [System.Text.Json.JsonSerializer] hat zwei Hauptmethoden:

    [T? Deserialize<T>(string json, JsonSerializerOptions? options = null)]
    rekonstruiert ein Objekt vom Typ [T] aus dem Text JSON [json]; löst eine [JsonException] aus, wenn der Text fehlerhaft ist

    5.8. Reguläre Ausdrücke

    Die Klasse [System.Text.RegularExpressions.Regex] unterstützt die Verwendung regulärer Ausdrücke. Damit lässt sich das Format einer Zeichenkette überprüfen. So können Sie beispielsweise verifizieren, dass eine Zeichenkette, die ein Datum darstellt, tatsächlich das Format dd/mm/yy hat. Dazu verwenden Sie ein Muster und vergleichen die Zeichenkette mit diesem Muster. In diesem Beispiel müssen d, m und y Ziffern sein. Das Muster für ein gültiges Datumsformat lautet daher [\d\d/\d\d/\d\d], wobei das Symbol [\d] für eine Ziffer steht. In einem Muster können folgende Symbole verwendet werden:

    Zeichen
    Beschreibung
    [\]
    markiert das folgende Zeichen als Sonderzeichen oder Literal. Beispielsweise entspricht [n] dem Zeichen n, [\n] einem Zeilenumbruch, [\\] dem Zeichen \ und [\(] dem Zeichen (
    [^]
    entspricht dem Anfang der Zeichenkette
    [$]
    entspricht dem Ende der Zeichenkette
    [*]
    entspricht dem vorhergehenden Element null- oder mehrmals. So passt [zo*] auf z oder zoo
    [+]
    entspricht dem vorhergehenden Element ein- oder mehrmals. So passt [zo+] auf „zoo“, aber nicht auf „z“
    [?]
    entspricht dem vorhergehenden Element null- oder einmal. Beispielsweise passt [a?ve?] auf „ve“ in „lever“
    [.]
    entspricht einem beliebigen einzelnen Zeichen außer einem Zeilenumbruch
    [(pattern)]
    sucht das Muster und speichert den Treffer (eine Gruppe). Der passende Teilstring kann aus der Sammlung [Groups] im Ergebnis extrahiert werden. Um Treffer mit Zeichen in Klammern zu finden, verwenden Sie [\(] oder [\)]
    [x|y]
    entspricht entweder x oder y. Beispielsweise passt [z|foot] auf z oder foot; [(z|f)oo] passt auf zoo oder foo
    [{n}]
    n ist eine nicht negative ganze Zahl. Entspricht genau n-mal dem vorhergehenden Element. Beispielsweise passt [o{2}] nicht auf das o in Bob, wohl aber auf die ersten beiden o in fooooot
    [{n,}]
    entspricht dem vorhergehenden Element mindestens n-mal. Beispielsweise passt [o{2,}] nicht auf das „o“ in „Bob“, wohl aber auf alle „o“ in „fooooot“. [o{1,}] ist gleichbedeutend mit [o+], und [o{0,}] ist gleichbedeutend mit [o*]
    [{n,m}]
    entspricht dem vorhergehenden Element mindestens n-mal und höchstens m-mal. Beispielsweise passt [o{1,3}] auf die ersten drei „o“ in „foooooot“; [o{0,1}] ist gleichbedeutend mit [o?]
    [xyz]
    Zeichenmenge: entspricht einem der angegebenen Zeichen. Beispielsweise passt [abc] auf den Buchstaben „a“ in „plat“
    [^xyz]
    negierte Zeichenmenge: entspricht jedem nicht aufgeführten Zeichen. Beispielsweise passt [^abc] auf „p“ in „plat“
    [a-z]
    Zeichenbereich: entspricht jedem Zeichen im angegebenen Bereich, hier einem Kleinbuchstaben ohne Akzent
    [^m-z]
    negierter Zeichenbereich: entspricht jedem Zeichen, das nicht zwischen „m“ und „z“ liegt
    [\b]
    entspricht einer Wortgrenze, also der Position zwischen einem Wortzeichen und einem Nicht-Wortzeichen. Beispielsweise passt [er\b] auf „er“ in „lever“, aber nicht auf „er“ in „verb“
    [\B]
    entspricht einer Position, die keine Wortgrenze ist. [en*t\B] entspricht „ent“ in „entertain“
    [\d]
    entspricht einer Ziffer; ist gleichbedeutend mit [0-9] (bei .NET auch für Ziffern aus anderen Unicode-Schriften)
    [\D]
    entspricht einem Zeichen, das keine Ziffer ist
    [\f], [\n], [\r], [\t], [\v]
    entsprechen den Zeichen Seitenvorschub, Zeilenumbruch, Wagenrücklauf, Tabulator beziehungsweise vertikaler Tabulator
    [\s]
    entspricht beliebigem Leerraum: Leerzeichen, Tabulator, Seitenvorschub, Zeilenumbruch … Gleichbedeutend mit [ \f\n\r\t\v], zuzüglich weiterer Unicode-Leerzeichen (geschütztes Leerzeichen usw.)
    [\S]
    entspricht jedem Zeichen, das kein Leerraumzeichen ist
    [\w]
    entspricht jedem Wortzeichen: Buchstabe (mit oder ohne Akzent), Ziffer oder Unterstrich
    [\W]
    entspricht jedem Zeichen, das kein Wortzeichen ist
    [\num]
    num ist eine positive ganze Zahl: verweist auf die Gruppe mit der Nummer num. Beispielsweise passt [(.)\1] auf zwei aufeinanderfolgende gleiche Zeichen
    [\xnn], [\unnnn]
    entspricht dem hexadezimalen Zeichen nn (2 Ziffern) oder nnnn (4 Ziffern). Beispielsweise entspricht [\x41] dem Zeichen A

    Ein Element in einem Muster kann einmal oder mehrfach vorkommen. Sehen wir uns einige Beispiele mit dem Symbol [\d], an, das eine einzelne Ziffer darstellt:

    Muster
    Bedeutung
    [\d]
    eine Ziffer
    [\d?]
    0 oder 1 Ziffer
    [\d*]
    0 oder mehr Ziffern
    [\d+]
    1 oder mehr Ziffern
    [\d{2}]
    2 Ziffern
    [\d{3,}]
    Mindestens 3 Ziffern
    [\d{5,7}]
    zwischen 5 und 7 Ziffern

    [\s*[+-]?\s*\d+(\.\d*)?\s*]
    eine Zeichenkette, die das Wort „just“ enthält
    [\bjust\b]

    Der Kurs von 2008 verwendete [+|-] für das Vorzeichen: In eckigen Klammern hat das Zeichen [|] keine besondere Bedeutung, und dieses Format akzeptierte auch das Zeichen | vor einer Zahl. Außerdem wurde [(.\d*)] für den Dezimalteil verwendet: Der dort nicht maskierte Punkt steht für ein beliebiges Zeichen. Die obigen Muster wurden korrigiert.

    Teilmuster eines Musters können „extrahiert“ werden. So können wir nicht nur prüfen, ob eine Zeichenkette einem bestimmten Muster entspricht, sondern auch die Elemente aus dieser Zeichenkette extrahieren, die den in Klammern eingeschlossenen Teilmustern entsprechen. Wenn Sie beispielsweise eine Zeichenkette mit einem Datum im Format dd/mm/yy analysieren und zusätzlich die Bestandteile dd, mm und yy dieses Datums extrahieren möchten, verwenden Sie das Muster [(\d\d)/(\d\d)/(\d\d)].

    In C#-Code schreibt man ein Muster vorzugsweise als wörtliche Zeichenkette (Verbatim-String) [@"..."]: So müssen die zahlreichen Zeichen [\] in den Mustern nicht verdoppelt werden. Bei einer normalen Zeichenkette müssten Sie stattdessen ***["\\\\d+"] schreiben statt ***[@"\\d+"].

Die Zahl der Möglichkeiten verdoppelt sich mit jedem zusätzlichen „a“: Bei 30 „a“ sind es etwa eine Milliarde Möglichkeiten. Dies nennt man katastrophales Backtracking. Ein solches Muster, das auf von Benutzern eingegebene Zeichenketten angewendet wird, ist eine Sicherheitslücke: Schon wenige Anfragen genügen, um einen Server zum Absturz zu bringen. Der Parameter [matchTimeoutMilliseconds] legt ein Timeout von 100 ms fest: Danach wird die Suche mit einer [RegexMatchTimeoutException] abgebrochen (Zeile 6);

// die aus einer Textdatei mit Zeilen limit:coeffR:coeffN gelesenen Steuerstufen
public partial class FileTax : AbstractTax
{

    // die aus der Datei gelesenen Steuerstufen

    // Implementierung der abstrakten Eigenschaft der Elternklasse
    protected override TaxBracket[] TaxBrackets => taxBrackets;

    public FileTax(string fileName)
    {
        // der Name der Datei, ohne Pfad, für die Fehlermeldungen
        string name = Path.GetFileName(fileName);
        // die gelesenen Stufen; ihre Anzahl kennen wir nicht im Voraus
        List<TaxBracket> brackets = [];
        try
        {
            int lineNumber = 0;
            foreach (string lineRead in File.ReadLines(fileName))
            {
                lineNumber++;
                string line = lineRead.Trim();
                // leere Zeilen werden ignoriert
                if (line == "")
                {
                    continue;
                }
                // die Zeile muss drei Felder haben
                string[] fields = Separator().Split(line);
                if (fields.Length != 3)
                {
                    throw new TaxException($"Line no. {lineNumber} is incorrect ({line})")
                    {
                        Code = (int)ErrorCode.Line
                    };
                }
                // drei positive oder null betragende Dezimalzahlen, mit Dezimalpunkt geschrieben
                ErrorCode code = 0;
                if (!Read(fields[0], out decimal limit)) code |= ErrorCode.Field1;
                if (!Read(fields[1], out decimal coeffR)) code |= ErrorCode.Field2;
                if (!Read(fields[2], out decimal coeffN)) code |= ErrorCode.Field3;
                if (code != 0)
                {
                    throw new TaxException($"Line no. {lineNumber} is incorrect ({line})")
                    {
                        Code = (int)code
                    };
                }
                // wir speichern die neue Steuerstufe
                brackets.Add(new TaxBracket(limit, coeffR, coeffN));
            }
        }
        catch (Exception e) when (e is IOException or UnauthorizedAccessException)
        {
            // Dateizugriffsfehler: wir verpacken ihn in eine TaxException
            throw new TaxException($"Error while reading the file {name}", e)
            {
                Code = (int)ErrorCode.Access
            };
        }
        // mindestens eine Stufe ist erforderlich
        if (brackets.Count == 0)
        {
            throw new TaxException($"The file {name} does not contain any bracket")
            {
                Code = (int)ErrorCode.Line
            };
        }
        // wir übertragen die Liste in das Array der Stufen
        taxBrackets = brackets.ToArray();

    private static bool Read(string field, out decimal result) =>

// Steuerberechnung, Version 3: die Steuerstufen werden aus einer Datei gelesen
// Syntax: dotnet run [-- Datei]; Datei: standardmäßig TaxData.txt oder eine .json-Datei

const string syntax = """
    syntax: Married NbChildren Salary
    Married: y for married, n for not married
    NbChildren: number of children
    Salary: annual salary in euros
    """;

// die Datendatei wird neben der ausführbaren Datei gesucht
string fileName = args.Length > 0 ? args[0] : "TaxData.txt";
string path = Path.Combine(AppContext.BaseDirectory, fileName);
Console.WriteLine($"Tax brackets read from [{fileName}]");

// Erzeugung eines ITax-Objekts; die Klasse hängt von der Dateierweiterung ab
ITax tax;
try
{
    tax = Path.GetExtension(fileName).ToLower() switch
    {
        ".json" => new JsonTax(path),
        _ => new FileTax(path)
    };
}
catch (TaxException e)
{
    // Anzeige des Fehlers; der Code wird als Kombination von ErrorCode angezeigt
    string origin = e.InnerException is null ? "" : $", original exception: {e.InnerException.GetType().Name}";
    Console.WriteLine($"The following error occurred: [Code={(ErrorCode)e.Code}, Message={e.Message}{origin}]");
    // Beenden des Programms
    return 1;
}

// Eingabeschleife
while (true)
{
    // wir fragen nach den Parametern der Steuerberechnung
    Console.Write("Tax calculation parameters in the format: Married (y/n) NbChildren Salary, or nothing to stop: ");
    string parameters = (Console.ReadLine() ?? "").Trim();
    // etwas zu tun?
    if (parameters == "")
    {
        break;
    }
    // Prüfung der Feldanzahl der eingegebenen Zeile
    string[] fields = parameters.Split(' ', StringSplitOptions.RemoveEmptyEntries);
    if (fields.Length != 3)
    {
        Console.WriteLine(syntax);
        continue;
    }
    // Prüfung der Gültigkeit der Parameter
    // married
    string married = fields[0].ToLower();
    if (married != "y" && married != "n")
    {
        Console.WriteLine(syntax + "\nIncorrect married argument: type y or n");
        continue;
    }
    // nbChildren
    if (!int.TryParse(fields[1], out int nbChildren) || nbChildren < 0)
    {
        Console.WriteLine(syntax + "\nIncorrect NbChildren argument: type a positive or zero integer");
        continue;
    }
    // salary
    if (!int.TryParse(fields[2], out int salary) || salary < 0)
    {
        Console.WriteLine(syntax + "\nIncorrect salary argument: type a positive or zero integer");
        continue;
    }
    // die Parameter sind korrekt: wir berechnen die Steuer
    Console.WriteLine($"Tax={tax.Calculate(married == "y", nbChildren, salary)} euros");
}
return 0;

    • Zeile 14: Der Name der Datendatei wird als Argument übergeben; standardmäßig ist es [TaxData.txt];
    • Zeile 15: Die Datei wird im Ordner der ausführbaren Datei gesucht, [AppContext.BaseDirectory], wohin sie bei der Kompilierung kopiert wurde. So findet das Programm seine Daten unabhängig davon, aus welchem Ordner es gestartet wird, was bei den Single-File-Anwendungen dieses Kapitels nicht der Fall war;
    • Zeilen 22–25: Ein [switch] -Ausdruck (Kapitel 3) wählt anhand der Dateierweiterung die zu instanziierende Klasse aus. Die beiden Zweige liefern unterschiedliche Typen, [JsonTax] und [FileTax]: Der Compiler leitet den Typ des Ausdrucks aus der Zielvariablen [tax] ab, die den Typ [ITax] hat ([switch] -Ausdruck mit Zieltyp).     5.10. Fazit

    Dieses Kapitel hat die .NET-Klassen vorgestellt, die in fast allen Programmen verwendet werden:

    • unveränderliche Zeichenketten ([string]) und veränderliche Zeichenketten ([StringBuilder]) zu ihrem stückweisen Aufbau; Interpolation mit Breiten und Formaten, Raw-Strings; Sichten ([ReadOnlySpan<char>]) für kritischen Code;
    • die Arrays und die Klasse [Array];
    • die generischen Sammlungen [List<T>], [Dictionary<TKey,TValue>], [HashSet<T>], [Queue<T>], [Stack<T>], [PriorityQueue<TElement,TPriority>] und ihre schreibgeschützten Schnittstellen; die nicht generischen Sammlungen [ArrayList] und [Hashtable] sind veraltet;
    • LINQ, seine Sequenzen [IEnumerable<T>], seine Iteratoren und seine verzögerte Ausführung;
    • Textdateien ([StreamReader], [StreamWriter], [File]), Binärdateien ([BinaryWriter], [BinaryReader]) und die JSON-Serialisierung, die die binäre Serialisierung von [BinaryFormatter] ersetzt, das aus .NET entfernt wurde;
    • reguläre Ausdrücke, vorzugsweise zur Kompilierzeit generiert und bei der Verarbeitung externer Daten stets durch ein Timeout geschützt.

    Die Beispielanwendung liest ihre Daten nun aus einer Textdatei oder aus JSON. Das folgende Kapitel gliedert sie in Schichten um: Das Lesen der Daten, die Steuerberechnung und die Benutzerinteraktion werden zu unabhängigen Komponenten.
