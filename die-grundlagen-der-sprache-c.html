    3. Die Grundlagen der Sprache C#

    3.1. Einführung

    Wir beginnen damit, C# als traditionelle Programmiersprache zu behandeln. Klassen behandeln wir im nächsten Kapitel. In einem Programm gibt es zwei Hauptbestandteile:

    • Daten;
    • die Anweisungen, die sie verarbeiten.

    Im Allgemeinen versucht man, Daten und Anweisungen voneinander zu trennen:

    Alle Beispiele in diesem Kapitel sind Einzeldatei-Anwendungen: eine einzige Datei [.cs] ohne Projektdatei ([.csproj]), die mit dem Befehl [dotnet run basics-01.cs] ausgeführt wird. Dieses mit .NET 10 eingeführte Feature wurde im vorigen Kapitel behandelt. Die Beispiele befinden sich im Ordner [03-basics] des Kurscodes. Sie laufen mit der französischen Ländereinstellung (fr-FR), wie auf einem französischen Windows-Rechner: Reelle Zahlen werden mit Dezimalkomma angezeigt.

    • Zeile 3: Die Methode [WriteLine] der Klasse [Console] gibt eine Zeile auf dem Bildschirm aus;
    • Zeile 5: Die Klasse [Console] gehört zum Namespace [System]. Ihr vollständiger Name lautet [System.Console]. Ein Namespace fasst zusammengehörige Typen zusammen, so wie ein Ordner Dateien zusammenfasst;
    • Zeile 5: Das Programm besitzt ein Array [args] mit den Befehlszeilenargumenten. Darauf kommen wir im Abschnitt „Argumente des Hauptprogramms“ zurück. Die Anzahl der Elemente des Arrays ist [args.Length]. Der Operator + verkettet hier eine Zeichenfolge und eine Zahl: Die Zahl wird zuvor in eine Zeichenfolge umgewandelt.

    Kommentare:

    • Zeile 2: Die Direktive [using] importiert den Namespace [System]. Man kann dann [Console] statt [System.Console] schreiben;
    • Zeile 4: Die Klasse befindet sich im Namespace [Basics]. Ab C# 10 kann man [namespace Basics;] schreiben (Namespace im Dateibereich): Die gesamte Datei gehört dann zu diesem Namespace, ohne geschweifte Klammern und ohne zusätzliche Einrückung. Diese Form verwenden wir von nun an;
    • Zeile 6: In C# gehört aller Code zu einer Klasse. Die Klasse heißt hier [Program];
    • Zeile 9: Die statische Methode [Main] ist der Einstiegspunkt des Programms: Es ist die Methode, die das System beim Start ausführt. Ihr Parameter [args], erhält die Befehlszeilenargumente.

    Die beiden Programme sind gleichwertig. Wenn der Compiler Top-Level-Anweisungen vorfindet, erzeugt er eine Klasse und eine Methode namens [Main] , die diese Anweisungen sowie den Parameter [string[] args] enthalten. Top-Level-Anweisungen sind also lediglich eine Kurzform der Standardsyntax. Sie eignen sich gut für die kleinen Programme dieses Kapitels; die Standardsyntax bleibt nützlich, wenn man die Klasse untersuchen möchte, die [Main] enthält.

    Oben haben wir für jeden C#-Typ den entsprechenden .NET-Typ aufgeführt, mit (S) gekennzeichnet, wenn der Typ eine Struktur ist, und mit (K), wenn er eine Klasse ist. Wir sehen, dass es für eine 32-Bit-Ganzzahl zwei mögliche Namen gibt: [int] und [Int32]. Der Typ [int] ist ein C#-Schlüsselwort. [Int32] ist eine Struktur, die zum Namespace [System] gehört: Ihr vollständiger Name lautet [System.Int32]. Der Typ [int] ist ein C#-Alias , der auf die .NET-Struktur [System.Int32] verweist. Ebenso ist der C#-Typ [string] ein Alias für den .NET-Typ [System.String]. [System.String] ist eine Klasse, keine Struktur. Die beiden Konzepte sind ähnlich, unterscheiden sich aber in folgendem grundlegenden Punkt:

    • Eine Variable vom Typ einer Struktur enthält ihren Wert direkt: Man spricht von einem Werttyp;
    • Eine Variable eines Klassentyps enthält die Adresse des Objekts (seine Referenz); man spricht von einem Referenztyp.

    Außerdem gibt es zwei weniger gebräuchliche Typen:

    • [nint] und [nuint] (C# 9) sind vorzeichenbehaftete und vorzeichenlose Ganzzahlen, deren Größe der einer Speicheradresse entspricht: 4 Bytes auf einem 32-Bit-System, 8 Bytes auf einem 64-Bit-System. Sie dienen vor allem der Interaktion mit nativem Code;
    • [System.Half] (.NET 5) ist eine 2 Byte große Gleitkommazahl mit geringer Genauigkeit, die in der Grafikberechnung und im maschinellen Lernen verwendet wird. Es ist kein vordefinierter Typ der Sprache: Es hat kein C#-Schlüsselwort.

    Eine Struktur ist wie eine Klasse ein komplexer Typ mit Eigenschaften und Methoden. So können wir schreiben:

    1
    string? typeName = 3.GetType().FullName;

    Das Literal 3 ist standardmäßig vom C#-Typ [int] und damit vom .NET-Typ [System.Int32]. Diese Struktur hat eine Methode [GetType()] , die ein Objekt zurückgibt, das den Datentyp beschreibt. Zu den Eigenschaften dieses Objekts gehört [FullName] , der vollständige Name des Typs. Das Literal 3 ist also ein komplexeres Objekt, als es auf den ersten Blick scheint. Das Fragezeichen in [string?] wird etwas später erklärt.

    Im Quelltext werden Gleitkommazahlen unabhängig von der Ländereinstellung des Systems immer mit Dezimalpunkt geschrieben. Seit C# 7 können Ganzzahlen binär geschrieben werden (mit dem Präfix [0b]), und Zifferngruppen können zur besseren Lesbarkeit durch das Zeichen _ getrennt werden: [1_000_000] ist die Ganzzahl eine Million.

    Ein normales Zeichenfolgenliteral kann Escape-Sequenzen enthalten, die durch das Zeichen \ eingeleitet werden: "\n" steht für das Zeilenendezeichen und nicht für die Folge der beiden Zeichen \ und n, "\t" steht für einen Tabulator, "\"" steht für ein doppeltes Anführungszeichen, und "\\" steht für das Zeichen \ selbst. Um den Windows-Pfad c:\chap1\paragraph3 zu schreiben, müssen Sie daher "c:\\chap1\\paragraph3" schreiben. Sie können auch @"c:\chap1\paragraph3" schreiben: Die Syntax @"text" legt fest, dass der Text genau so übernommen wird, wie er geschrieben ist, ohne das Zeichen \ zu interpretieren. Man spricht von einer wörtlichen Zeichenfolge (Verbatim-String).

    C# bietet inzwischen zwei weitere Arten von Zeichenfolgen:

    • die interpolierte Zeichenfolge (C# 6) $"...": Ausdrücke in geschweiften Klammern werden ausgewertet, und ihre Werte werden in die Zeichenfolge eingefügt. Auf einen Ausdruck kann nach einem Doppelpunkt eine Formatangabe folgen: [$"{d1:F2}"] zeigt die Gleitkommazahl [d1] mit zwei Nachkommastellen an. Dies ist die lesbarste Art, eine Zeichenfolge zu konstruieren, und wir werden sie von nun an anstelle der Formate {0}, {1}, ... verwenden;
    • Die Rohzeichenfolge (C# 11) """...""": Sie beginnt und endet mit mindestens drei Anführungszeichen. Sie kann Anführungszeichen und \-Zeichen ohne Escape enthalten und sich über mehrere Zeilen erstrecken. Leerzeichen vor den schließenden Anführungszeichen werden aus jeder Zeile entfernt, sodass der Text mit dem Code eingerückt werden kann. Das ist sehr nützlich zum Schreiben von JSON, SQL oder HTML.

    3.3.3. Deklaration von Daten

    3.3.3.1. Aufgabe von Deklarationen

    Ein Programm verarbeitet Daten, die durch einen Namen und einen Typ gekennzeichnet sind. Diese Daten werden im Speicher abgelegt. Beim Kompilieren des Programms weist der Compiler jedem Datum einen Speicherplatz zu, der durch eine Adresse und eine Größe gekennzeichnet ist. Dabei stützt er sich auf die Deklarationen des Programmierers. Außerdem ermöglichen diese Deklarationen dem Compiler, Programmierfehler zu erkennen. So wird die Operation [x = x * 2;] als ungültig abgelehnt, wenn [x] eine Zeichenfolge ist.

    3.3.3.2. Konstanten deklarieren

    Die Syntax zur Deklaration einer Konstante lautet:

    1
    const type name = value;

    Zum Beispiel:

    1
    const double VatRate = 0.2;

    Warum Konstanten deklarieren?

    • Das Programm ist leichter lesbar, wenn die Konstante einen aussagekräftigen Namen erhält;
    • das Programm lässt sich leichter ändern, wenn die „Konstante“ angepasst werden muss. Ändert sich beispielsweise der Mehrwertsteuersatz auf 0,25, ist nur die Anweisung zu ändern, die seinen Wert festlegt: [const double VatRate = 0.25;]. Wäre 0,2 explizit im Programm verwendet worden, müssten zahlreiche Anweisungen geändert werden.

    Der Wert einer Konstante muss zur Kompilierzeit bekannt sein: eine Zahl, eine Zeichenfolge, ein boolescher Wert oder ein Ausdruck, der sich aus anderen Konstanten berechnen lässt. In .NET beginnen Konstantennamen üblicherweise mit einem Großbuchstaben.

    3.3.3.3. Deklaration von Variablen

    Eine Variable wird durch einen Namen identifiziert und ist einem Datentyp zugeordnet. C# unterscheidet zwischen Groß- und Kleinschreibung: Die Variablen [END] und [end] sind verschieden.

    Variablen können bei ihrer Deklaration initialisiert werden. Die Syntax zur Deklaration einer oder mehrerer Variablen lautet:

    1
    type variable1 = value1, variable2 = value2, ...;

    Dabei ist [type] ein vordefinierter oder ein vom Programmierer definierter Typ. Die Initialisierung ist optional; C# erlaubt jedoch nicht die Verwendung einer lokalen Variable, der noch kein Wert zugewiesen wurde.

    Sie können den Typ einer Variable auch weglassen, indem Sie anstelle des Typs das Schlüsselwort [var] verwenden:

    1
    var variable1 = value1;

    Das Schlüsselwort [var] bedeutet nicht, dass die Variable keinen bestimmten Typ hätte: Sie hat den vom Compiler ermittelten Typ des ihr zugewiesenen Werts. Die Initialisierung ist hier erforderlich, damit der Compiler den Typ ableiten kann. Wir verwenden [var] , wenn der Typ aus dem Wert offensichtlich ist.

    3.3.4. Nullable-Typen

    Eine Variable eines Werttyps wie [int] enthält immer einen Wert. Manchmal ist es nützlich, das Fehlen eines Werts ausdrücken zu können: ein unbekanntes Alter, ein leeres Feld in einer Datenbank. Der Typ [int?] (C# 2) ist der Typ [int] , erweitert um den Wert [null], der „kein Wert“ bedeutet. Man spricht von einem Nullable-Werttyp. Das Prinzip gilt für alle Werttypen: [double?], [bool?], [DateTime?], ...

    Eine Variable eines Referenztyps wie [string] kann immer den Wert [null] haben: Das bedeutet, dass sie auf kein Objekt verweist. Der Versuch, einen Member einer solchen Variable zu verwenden, etwa ihre Eigenschaft [Length], führt zu einem Laufzeitfehler ([NullReferenceException]), einem der häufigsten Fehler in C#. Ab C# 8 kann der Compiler dies verhindern helfen: mit Nullable-Referenztypen, die in mit dem Befehl [dotnet new] erstellten Projekten und in Einzeldatei-Anwendungen standardmäßig aktiviert sind, gilt:

    • der Typ [string] bezeichnet eine Zeichenfolge, die niemals den Wert [null] hat;
    • der Typ [string?] bezeichnet eine Zeichenfolge, die [null] sein kann.

    Der Compiler verfolgt die möglichen Werte von Variablen und gibt eine Warnung aus, wenn die Gefahr besteht, den Wert [null] zu verwenden: [null] einer Variable [string] zuzuweisen, [Length] auf eine nicht geprüfte Variable [string?] anzuwenden usw. Anders als [int?] erzeugt [string?] zur Laufzeit keinen neuen Typ: Es ist eine für den Compiler bestimmte Anweisung.

    3.3.6. Datenarrays

    Ein C#-Array ist ein Objekt, mit dem sich Daten desselben Typs unter einem einzigen Bezeichner zusammenfassen lassen. Es wird wie folgt deklariert:

    1
    Type[] array = new Type[n];

    [n] ist die Anzahl der Datenelemente, die das Array enthalten kann. Die Syntax [array[i]] bezeichnet das Datenelement Nummer i, wobei i im Bereich [0, n-1] liegt. Jeder Zugriff auf das Datenelement [array[i]] mit einem i außerhalb des Bereichs [0, n-1] löst eine Ausnahme aus. Bei der Erzeugung erhält jedes Element des Arrays den Standardwert seines Typs: 0 für Zahlen, [false] für boolesche Werte und [null] für Referenztypen. Ein Array kann gleichzeitig mit seiner Deklaration initialisiert werden:

    1
    int[] integers = new int[] { 0, 10, 20, 30 };

    oder einfacher:

    1
    int[] integers = { 0, 10, 20, 30 };

    oder ab C# 12 mit einem Collection-Ausdruck:

    1
    int[] integers = [0, 10, 20, 30];

    Diese letzte Form verwenden wir von nun an. Arrays haben eine Eigenschaft [Length], die die Anzahl der enthaltenen Elemente angibt.

    Ein zweidimensionales Array wird wie folgt deklariert:

    1
    Type[,] array = new Type[n, m];

    Dabei ist [n] die Anzahl der Zeilen und [m] die Anzahl der Spalten. Die Syntax [array[i, j]] bezeichnet das Element j der Zeile i. Das zweidimensionale Array kann ebenfalls gleichzeitig mit seiner Deklaration initialisiert werden:

    1
    double[,] reals = { { 0.5, 1.7 }, { 8.4, -6 } };

    Die Anzahl der Elemente in jeder Dimension erhält man mit der Methode [GetLength(i)], wobei i=0 die Dimension des ersten Index, i=1 die Dimension des zweiten Index usw. darstellt. Die Anzahl der Dimensionen erhält man mit der Eigenschaft [Rank], die Gesamtzahl der Elemente mit der Eigenschaft [Length].

    Ein Array von Arrays (auch gezacktes Array genannt) wird wie folgt deklariert:

    1
    Type[][] array = new Type[n][];

    Die obige Deklaration erzeugt ein Array mit n Elementen. Jedes Element [array[i]], ist eine Referenz auf ein eindimensionales Array. Diese Referenzen werden von der obigen Deklaration nicht initialisiert; sie haben den Wert [null]. Anders als bei einem zweidimensionalen Array kann jede Zeile eine andere Länge haben.

    C# 8 hat zwei praktische Schreibweisen eingeführt:

    • die Indizierung von hinten: [array[^1]] ist das letzte Element, [array[^2]] ist das vorletzte usw. [array[^1]] entspricht [array[array.Length - 1]];
    • der Bereich: [array[1..3]] ist ein neues Array aus den Elementen mit den Indizes 1 und 2. Der Startindex ist eingeschlossen, der Endindex ausgeschlossen. Die Grenzen können weggelassen werden: [array[2..]] reicht von Index 2 bis zum Ende, und [array[..^1]] reicht vom Anfang bis einschließlich zum vorletzten Element.

    3.4. Grundlegende C#-Anweisungen

    Es gibt:

    • grundlegende Anweisungen, die der Computer ausführt;
    • Anweisungen, die den Programmablauf steuern.

    Die grundlegenden Anweisungen werden verständlich, wenn man den Aufbau eines Mikrocomputers und seiner Peripheriegeräte betrachtet:

    • 1: Informationen von der Tastatur lesen;
    • 2: Informationen verarbeiten;
    • 3: Informationen auf den Bildschirm schreiben.

    3.4.1. Auf den Bildschirm schreiben

    Es gibt verschiedene Anweisungen zum Schreiben auf den Bildschirm:

    1
2
3
    Console.Out.WriteLine(expression);
Console.WriteLine(expression);
Console.Error.WriteLine(expression);

    Dabei ist [expression] ein beliebiges Datum, das sich zur Anzeige auf dem Bildschirm in eine Zeichenfolge umwandeln lässt. Alle C#- oder .NET-Objekte haben eine Methode [ToString()], mit der diese Umwandlung erfolgt. Die Methode [Write] tut dasselbe wie [WriteLine] , jedoch ohne Zeilenumbruch.

    Die Klasse [System.Console] bietet Zugriff auf Schreiboperationen für den Bildschirm ([Write], [WriteLine]). Sie hat zwei Eigenschaften, [Out] und [Error], die Schreibströme vom Typ [TextWriter] sind:

    • [Console.WriteLine()] entspricht [Console.Out.WriteLine()] und schreibt in den Strom [Out], der üblicherweise dem Bildschirm zugeordnet ist;
    • [Console.Error.WriteLine()] schreibt in den Strom [Error], der ebenfalls üblicherweise dem Bildschirm zugeordnet ist.

    Die Ströme [Out] und [Error] können zur Laufzeit in Dateien umgeleitet werden, wie wir gleich sehen werden.

    3.4.2. Über die Tastatur eingegebene Daten lesen

    Der Datenstrom der Tastatur wird durch das Objekt [Console.In] vom Typ [TextReader] dargestellt. Dieser Objekttyp erlaubt es, mit der Methode [ReadLine] eine Textzeile zu lesen:

    1
    string? line = Console.In.ReadLine();

    Die Klasse [Console] stellt eine Methode [ReadLine] bereit, die standardmäßig dem Strom [In] zugeordnet ist. Daher können Sie schreiben:

    1
    string? line = Console.ReadLine();

    Die über die Tastatur eingegebene Zeile wird ohne das Zeilenendezeichen in der Variable [line] gespeichert und kann anschließend vom Programm verarbeitet werden. Wie wir gesehen haben, gibt [ReadLine] den Wert [null] zurück, wenn der Eingabestrom erschöpft ist: Deshalb hat die Variable den Typ [string?]. Der Strom [In] kann wie die Ströme [Out] und [Error] in eine Datei umgeleitet werden.

    3.4.5. Zuweisung des Werts eines Ausdrucks an eine Variable

    Hier betrachten wir die Operation [variable = expression;]. Der Ausdruck kann arithmetisch, relational, boolesch, eine Zeichenkette usw. sein.

    3.4.5.1. Interpretation der Zuweisungsoperation

    Die Operation [variable = expression;] ist selbst ein Ausdruck, der wie folgt ausgewertet wird:

    • die rechte Seite der Zuweisung wird ausgewertet: Das Ergebnis ist ein Wert V;
    • der Wert V wird der Variablen zugewiesen;
    • der Wert V ist zugleich der Wert der Zuweisung, die nun als Ausdruck betrachtet wird.

    Somit ist die Operation [V1 = V2 = expression] gültig. Da der Operator = von rechts nach links ausgewertet wird, erhalten wir [V1 = (V2 = expression)]. Der Ausdruck [V2 = expression] wird ausgewertet und hat den Wert V. Durch seine Auswertung wurde V an V2 zugewiesen. Anschließend wird der nächste Operator = als [V1 = V] ausgewertet. Der Wert dieses Ausdrucks ist weiterhin V; seine Auswertung bewirkt, dass V an V1 zugewiesen wird. Die Operation [V1 = V2 = expression] ist also ein Ausdruck, dessen Auswertung:

    • bewirkt, dass der Wert von [expression] den Variablen V1 und V2 zugewiesen wird;
    • den Wert von [expression] zurückgibt.

    Dies lässt sich auf einen Ausdruck der Form [V1 = V2 = ... = Vn = expression] verallgemeinern.

    3.4.5.3. Reihenfolge der Auswertung arithmetischer Ausdrücke

    Bei der Auswertung eines arithmetischen Ausdrucks gilt die folgende Reihenfolge (von der höchsten zur niedrigsten Priorität):

    1
    [functions], [( )], [*, /, %], [+, -]

    Operatoren innerhalb desselben Blocks [ ] haben dieselbe Priorität. Bei gleicher Priorität erfolgt die Auswertung von links nach rechts: 10 - 4 - 3 wird als (10 - 4) - 3 = 3 ausgewertet.

    3.4.5.4. Relationale Ausdrücke

    Die Operatoren sind: <, <=, ==, !=, >, >=. Ihre Priorität ist:

    • >, >=, <, <=;
    • ==, !=.

    Das Ergebnis eines relationalen Ausdrucks ist der boolesche Wert [false] , wenn der Ausdruck falsch ist, andernfalls [true].

    Sie werden Zeichen für Zeichen verglichen. Die erste Ungleichheit, die zwischen zwei Zeichen auftritt, führt zu einer Ungleichheit derselben Richtung für die Zeichenketten. Betrachten Sie den Vergleich der Zeichenketten „Cart“ und „Cat“:

    Funktionen zum Vergleich zweier Zeichenketten

    Mit den relationalen Operatoren == und != können Sie testen, ob zwei Zeichenketten gleich sind, oder mit der Methode [Equals] der Klasse [System.String].     • positiv, wenn Zeichenkette 1 größer ist als Zeichenkette 2;

    3.4.5.5. Boolesche Ausdrücke

    Als Operatoren stehen UND (&&), ODER (||) und NICHT (!) zur Verfügung. Das Ergebnis eines booleschen Ausdrucks ist ein boolescher Wert. Operatorpriorität:

    • ! ;
    • && ;
    • ||.
    1
2

    Relationale Operatoren haben eine höhere Priorität als die Operatoren && und ||. Diese beiden Operatoren werten ihren rechten Operanden nur aus, wenn es nötig ist: In [a && b] wird b nicht ausgewertet, wenn a falsch ist; in [a || b] wird b nicht ausgewertet, wenn a wahr ist.     3.4.5.7. Kombination von Operatoren

    [a = a + b] kann als [a += b] geschrieben werden; [a = a - b] kann als [a -= b] geschrieben werden. Dasselbe gilt für die Operatoren /, %, *, <<, >>, >>>, &, |, ^. So kann [a = a / 2;] als [a /= 2;] geschrieben werden.

    3.4.5.8. Inkrement- und Dekrementoperatoren

    Die Schreibweise [variable++] bedeutet [variable = variable + 1] oder [variable += 1]. Die Schreibweise [variable--] bedeutet [variable = variable - 1] oder [variable -= 1]. In einem Ausdruck haben diese Operatoren zwei Formen:

    • [i++] (Postfix): Der Wert des Ausdrucks ist der Wert von i vor dem Inkrement;
    • [++i] (Präfix): Der Wert des Ausdrucks ist der Wert von i nach dem Inkrement.

    3.4.5.9. Der ternäre Operator ?:

    Der Ausdruck [expr_cond ? expr1 : expr2] wird wie folgt ausgewertet:

    • Der Ausdruck [expr_cond] wird ausgewertet. Es handelt sich um einen booleschen Ausdruck;
    • ist er wahr, ist der Wert des Ausdrucks der von [expr1], und [expr2] wird nicht ausgewertet;
    • ist er falsch, geschieht das Gegenteil: Der Wert des Ausdrucks ist der von [expr2], und [expr1] wird nicht ausgewertet.

    Die Operation [i = (j > 4 ? j + 1 : j - 1);] weist der Variablen i den Wert j+1 zu, wenn j > 4 gilt, andernfalls j-1. Das entspricht der Schreibweise [if (j > 4) i = j + 1; else i = j - 1;], ist aber kompakter.

    3.4.5.12. Typumwandlung

    In einem Ausdruck ist es möglich, die Darstellung eines Werts vorübergehend zu ändern. Man spricht von „Typumwandlung“ (Type Casting). Die Syntax zur Änderung des Typs eines Werts in einem Ausdruck lautet wie folgt:

    1
    (type) value

    Der Wert nimmt dann den angegebenen Typ an. Dies führt zu einer Änderung der Darstellung des Werts. Man unterscheidet:

    • implizite Konvertierungen, die der Compiler automatisch durchführt, wenn dabei keine Information verloren geht: von einem [int] in einen [long], von einem [int] in einen [double], von einem [char] in einen [int] und so weiter. Auch die Konvertierung von einem [long] in einen [double] erfolgt implizit, obwohl sie jenseits von 2⁵³ an Genauigkeit verlieren kann;
    • explizite Konvertierungen, bei denen Information verloren gehen kann und die der Programmierer mit der Schreibweise (Typ) ausdrücklich anfordern muss: von einem [double] in einen [int] (der Nachkommateil geht verloren), von einem [long] in einen [int] (die höchstwertigen Bits gehen verloren) usw.

    Standardmäßig wird ein Überlauf bei einer Ganzzahlberechnung oder einer Ganzzahlkonvertierung nicht gemeldet: Das Ergebnis ist schlicht falsch. Das Schlüsselwort [checked] bewirkt dagegen, dass ein Überlauf eine [OverflowException]-Ausnahme auslöst. Es lässt sich auf einen Ausdruck anwenden, [checked(expression)], oder auf einen Anweisungsblock, [checked { ... }].

    3.5.1. Anhalten

    Die Methode [Exit] der Klasse [Environment] erlaubt es, die Ausführung eines Programms anzuhalten:

    1
    Environment.Exit(int status);

    [Exit] beendet den aktuellen Prozess und gibt die Kontrolle an den aufrufenden Prozess zurück, in der Regel den Befehlsinterpreter. Der Wert von [status], der Rückgabecode genannt wird, kann vom Befehlsinterpreter ausgewertet werden. Per Konvention bedeutet 0, dass das Programm erfolgreich beendet wurde, jeder andere Wert zeigt einen Fehler an. Unter Windows steht der Rückgabecode in der Eingabeaufforderung in der Variablen [%ERRORLEVEL%] und in PowerShell in der Variablen [$LASTEXITCODE] zur Verfügung; unter Linux und macOS steht er in der Variablen [$?] der Shell zur Verfügung. Somit:

    1
    Environment.Exit(0);

    beendet das Programm mit dem Rückgabecode 0. Bei Anweisungen auf oberster Ebene beendet auch eine [return]-Anweisung das Programm (Rückgabecode 0), sofern sie sich nicht innerhalb einer Funktion befindet.

    3.8. Argumente des Hauptprogramms

    Die Hauptfunktion [Main] kann ein Array von Zeichenketten [string[]] als Parameter entgegennehmen. Dieses Array enthält die Kommandozeilenargumente, mit denen die Anwendung gestartet wurde. Wird das Programm P also mit dem folgenden Befehl gestartet:

    1
    P arg0 arg1 ... argn

    und ist die Funktion [Main] wie folgt deklariert:

    1
            static void Main(string[] args)

    Bei [dotnet run] werden die Argumente für das Programm hinter zwei Bindestrichen ([--]) angegeben, die sie von den Optionen des Befehls [dotnet run] selbst trennen:

    1
    dotnet run prog.cs -- a0 a1 a2

    3.9. Aufzählungen

    Eine Aufzählung (Enumeration) ist ein Datentyp, dessen Wertebereich aus einer Menge benannter ganzzahliger Konstanten besteht. Betrachten Sie ein Programm, das Prüfungsnoten verarbeiten soll. Es gibt fünf mögliche Bewertungen: Pass, FairlyGood, Good, VeryGood und Excellent. Wir können dann für diese fünf Konstanten eine Aufzählung definieren:

    1

    Intern werden diese fünf Konstanten als aufeinanderfolgende ganze Zahlen codiert, beginnend mit 0 für die erste Konstante, 1 für die nächste und so weiter. Wir können diese Werte auch explizit festlegen: [enum Honours { Pass = 10, FairlyGood = 12, ... }]. Eine Variable kann so deklariert werden, dass sie ihre Werte aus der Aufzählung bezieht:

    1

    3.10.1. Übergabemodi

    C# unterstützt die folgenden Übergabemodi:

    • als Wert (der Standardmodus): Der Wert des aktuellen Parameters wird in den entsprechenden formalen Parameter kopiert. Es sind zwei getrennte Entitäten: Ändert die Funktion den formalen Parameter, bleibt der aktuelle Parameter unverändert. Dieser Modus eignet sich für Eingabeparameter einer Funktion;
    • als Referenz mit [ref]: Der aktuelle und der formale Parameter sind ein und dieselbe Entität. Ändert die Funktion den formalen Parameter, wird auch der aktuelle Parameter geändert. Das Schlüsselwort [ref] muss sowohl in der Funktionsdefinition als auch im Aufruf stehen. Der aktuelle Parameter muss vor dem Aufruf einen Wert haben. Dieser Modus eignet sich für Ein-/Ausgabeparameter;
    • als Referenz mit [out]: wie [ref], aber der Parameter ist ein reiner Ausgabeparameter: Der aktuelle Parameter braucht keinen Anfangswert, und die Funktion muss dem formalen Parameter einen Wert zuweisen. Dieser Modus wird von den Methoden [TryParse] verwendet. Ab C# 7 kann die Variable im Aufruf deklariert werden: [out var x] oder [out int x];
    • als schreibgeschützte Referenz mit [in] (C# 7.2): Der Parameter wird per Referenz übergeben, was das Kopieren vermeidet, aber die Funktion kann ihn nicht ändern. Dieser Modus ist nur bei großen Strukturen sinnvoll; bei vordefinierten Typen ist die Übergabe als Wert ebenso effizient.

    3.11. Lokale Funktionen und Tupel

    3.11.1. Lokale Funktionen

    Eine lokale Funktion (C# 7) ist eine Funktion, die innerhalb einer Methode oder, wie in unseren Beispielen, zwischen Anweisungen auf oberster Ebene definiert wird. Sie kann nur an dieser Stelle verwendet werden. Da unsere Programme keine Klassen mehr haben, ersetzen lokale Funktionen die statischen Methoden der Beispiele von 2008. Eine lokale Funktion:

    • kann vor ihrer Definition aufgerufen werden;
    • kann die sie umgebenden lokalen Variablen verwenden, sofern sie nicht als [static] deklariert ist: Das Schlüsselwort [static] (C# 8) stellt sicher, dass sie nur von ihren Parametern abhängt, was sie leichter verständlich macht. Wir deklarieren unsere lokalen Funktionen nach Möglichkeit als [static];
    • kann einen Ausdruckskörper haben: [static int Square(int x) => x * x;] ist gleichwertig mit einem Rumpf wie [{ return x * x; }].

    In einem größeren Programm schreiben wir Klassen und Methoden: Das ist das Thema des nächsten Kapitels.

    3.11.2. Tupel

Ein Tupel kann dekonstruiert werden: [var (number, name) = t;] weist seine Elemente zwei Variablen zu.

    Mit Tupeln kann eine Funktion mehrere Werte zurückgeben, ohne [out]-Parameter zu verwenden: Das ist oft lesbarer.
